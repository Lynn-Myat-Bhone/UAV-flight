Introduction
Context & Domain: UAVs are widely deployed across mission-critical applications including delivery logistics, mapping, and industrial inspection.
Problem Statement: In-flight component degradations—such as motor malfunctions or actuator failures—pose severe risks of lost payloads and catastrophic ground collisions.
Core Goal: Build a data-driven framework for real-time fault detection and early anomaly prediction using high-frequency flight telemetry.

Identifiers 
bag, timestamp_ns 
Identify each UAV flight and preserve the chronological order of measurements. 
Control Commands 
roll_cmd, pitch_cmd, yaw_cmd 
Desired aircraft attitude commanded by the autopilot. 
Measured Response 
roll_meas, pitch_meas, yaw_meas, vel_x, vel_y, vel_z, ground_speed 
Actual aircraft attitude and motion measured by onboard sensors. 
Derived Features 
roll_error, pitch_error, yaw_error 
Difference between commanded and measured values, representing tracking accuracy and control performance. 
Orientation 
imu_x, imu_y, imu_z 
IMU quaternion components describing the UAV's orientation in 3D space. 
Ground Truth Labels 
engine_fault, aileron_fault, elevator_fault, rudder_fault 
Fault labels indicating the presence and type of fault during the flight.

Critical Data Quality Issues Found in Raw Data
Missing Values (NaNs):
timestamp_ns & airspeed_*:132937 rows (Complete).
pitch_*: 132937  rows (23 missing values).
yaw_*: 132937  rows (21 missing values).
vel_x, vel_y, vel_z: 172,480 rows (8,318 missing values missing!).
Fix :  forward-fill and backward fill  NaNs per flight segment 

Raw yaw_error Discontinuity:
Min: -358.79, Max: +358.99.
Observation: Raw yaw_error spans nearly  360 due to standard 180 compass wrap-around leaps. Angle wrapping to -180, +180  is mandatory.


Need normalize for yaw error problem
Problem
errors: Direct subtraction (Target- Measured) across North yields fake massive numbers:
Math calculation: 1-359 = -358
Physical reality: The plane is off by only +2 (tiny turn)
Misleads AI models: The machine learning algorithm mistakes these artificial -358spikes for catastrophic crashes rather than minor 2 drifts.
Fix: Angle wrapping formula:
Clean Error = (Raw Error + 180 ) (mod 360) -180

Shortest physical path: Restricts all errors strictly within [-180,180]:
Math calculation: (-358 + 180)mod9360) - 180 = 2
Clean data: Removes artificial math spikes, leaving true flight performance signals for model training.


Added Ground_speed
Calculate a 3D Ground Speed Proxy by applying the Euclidean Norm to your fully functional localized velocity channels (vel_x, vel_y, vel_z) 

Ground_Speed = sqrt( (vel_x)^2 + (vel_y)^2 + (vel_z)^2 ) 

Adding Fault_onset and fault within 5s

Binary_fault : describes the current fault state: 0 = normal ,  1 = currently faulty
However, for predictive modeling, we need to identify the exact moment when the system changes from normal to fault.

fault_within_5s: for every frame (within a single flight), look forward `horizon_sec = 5.0` seconds and check whether a `fault_onset` occurs in that window.


Normal distribution check

Distribution Breakdown
Imu_z : Right-Skewed / Bimodal:Main density centered at -1.0 with a long right-hand tail and secondary hump near 0.0.
Ground_speed:  Bimodal (Two Distinct Peaks):Not normal. It has two separate density modes: one peak at 0 (idle/ground/crash states) and a second main peak around 17 m/s (cruise speed). A normal distribution can only ever have one central peak.
vel_x : Trimodal (Three Peaks):Has three distinct operational modes centered around -20 m/s, 0m/s and +18 m/s
yaw_error_clean : Multimodal (Multiple Wave Peaks):Features multiple sharp peaks scattered across -170, -70, 0, and +110. These multiple modes reflect discrete spiraling and heading lock states.
roll_error & pitch_error : Leptokurtic (Heavy-Tailed / Non-Gaussian):While they look somewhat "bell-shaped" at first glance because of the tall center spike at 0, they violate normal distribution rules in two ways:
Fat Tails: Extremely long, flat tails extending out past +-60 to +- 100.
Asymmetry: The blue faulty distribution on roll_error has a secondary shoulder hump around -30, which never occurs in a normal curve.


Feature Scaling
Feature scaling is applied because the sensor and control variables have very different numerical ranges.
I used Standard scaler because it preserves Normal Distribution & Unbounded Ranges
